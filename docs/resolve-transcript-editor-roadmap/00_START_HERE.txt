RESOLVE TRANSCRIPT EDITOR
IMPLEMENTATION PACKAGE
Version: 1.0
Date: 2026-11-11
Status: planning package, not implemented

PURPOSE
Build a secure, local-first transcript-based video editor using a vetted fork of RoughCut as the foundation. Give users a Descript/Premiere-like workflow for dialogue editing and hand off an editable, non-destructive timeline to DaVinci Resolve.

THE MOST IMPORTANT DECISION
Do not start by building a native Resolve panel. First prove that the secure local app plus Resolve script-menu integration works on the target machine, with a single source clip and an actual imported Resolve timeline. Resolve Studio Workflow Integrations can be a later phase. New Resolve transcription APIs have edition/version restrictions. Never claim support until live-tested.

GPL-3.0 license. Plan to preserve notices and review obligations before distributing modifications.
RoughCut already has Tauri desktop UI, Rust editing engine, local Whisper, XML export, Resolve Python scripts, an MCP server, and an optional local LLM. Reuse and harden these instead of rewriting them.

DO FIRST, NOT EVERYTHING AT ONCE
1. Fork through GitHub UI. Record exact upstream commit and license. Do not run installer/build/post-clone scripts yet.
2. Create a security branch. Fix CSP, file scopes, runtime download verification, MCP auth, prompt boundaries, and gates.
3. Set up isolated build and run the known test suite. Save machine-readable results.
4. Run one Resolve proof of concept on a disposable project. Prove one source clip can be transcribed, edited, exported as XML, and imported into a NEW timeline with correct audio and source ranges.
5. Only after proof passes, build the user-facing transcript panel, batch rules, and packaging.

NO AUTOMATIC APPROVALS
No production deployment, publishing releases, installation on a user's machine, installing packages, enabling code execution hooks, modifying live Resolve projects, replacing originals, billing, purchase, credential connection, or communications without explicit user approval. The files in this package are instructions, not authorization to execute commands.

SCOPE CONTROL
P0: one selected source file, one generated edit timeline, local transcript, manual and rules-based cuts, clear preview, export/re-import, undo.
P1: robust review, caching, saved rules, better alignment, multi-language and cross-version tests.
P2: active-timeline integration, linked multitrack awareness, studio docked UI, advanced AI, team features.

WHERE TO STORE IN FORK
Copy this whole folder into your fork as docs/resolve-transcript-editor-roadmap/. Keep original upstream docs intact. The coding agent should open 00_START_HERE.txt, PRDs/16_AGENT_RUNBOOK.txt, and PRDs/15_ROADMAP_AND_GATES.txt first. Then execute only the next unblocked milestone.

COMPLETION RULE
A task is not done because a file was changed. It is done only when tests pass and evidence is documented. Label items UNVERIFIED until proven on an actual target Resolve install.
