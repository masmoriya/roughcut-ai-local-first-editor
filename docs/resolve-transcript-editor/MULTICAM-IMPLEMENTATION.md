# Implementation plan: Resolve multicam transcript editing

Read [the PRD](MULTICAM-PRD.md), [current status](PRD-STATUS.md), and [local verification](LOCAL-VERIFICATION.md) first. Work in the current RoughCut checkout and preserve existing changes.

1. **Prove the Resolve edit path.** Read the installed Resolve scripting declarations and inspect a disposable BTN project. Find a supported way to split and ripple remove a frame range on a duplicate while preserving nested multicam relationships. The installed declarations previously showed duplication and whole-item deletion, with no documented arbitrary-frame split. Evaluate a native edit workflow and an interchange round trip against the same preservation criteria. Keep experiments out of production code until one passes. If neither passes, record exactly what was lost and continue independent work without exposing an unverified Apply action.
2. **Bind the transcript to a timeline.** Extend the Rust project model with a versioned Resolve timeline binding, including stable identity, revision evidence, rate, frame origin and playback reference. Preserve existing single-file projects. Reuse timed import and transcript review. Validate mappings before enabling edits. Exercise nonzero starts, fractional rates, and version mismatch using focused tests.
3. **Build the cut plan and UI.** Reuse the existing cut planner and transcript selection. Add the Resolve source chooser or local snapshot import required by the verified bridge. Show the selected timeline, timing readiness, and reviewed removals. Persist the source frame ranges and verify stale-plan rejection across reopen.
4. **Integrate the proven local apply path.** Revalidate the selected timeline and idle status, create a uniquely named duplicate, perform cuts transactionally where supported, and verify the result before reporting success. Keep an idempotent job receipt and handle partial writes without affecting the original. Keep this integration local and narrowly scoped.
5. **Verify and package.** Use the mounted Extreme SSD read-only for inputs. The Episode 10 original export and keep-02.json are a verified timing pair for the previous single-video test. Independently establish the matching multicam timeline revision before reusing that pair. The SSD also contains Recovered_multicam.drp as a candidate for a disposable Resolve test. Run the PRD acceptance cases, focused security checks, and the normal locked native build with networking blocked. Record the Resolve version, bridge used, tests, and remaining gaps.

Use the existing authorization for the normal Cargo build scripts. Keep the user's restriction on executing other scripts they have not supplied. Only interact with Resolve after verifying it is idle. Preserve unrelated Git changes, and limit lint and type checks to the authorized build and affected scope.
